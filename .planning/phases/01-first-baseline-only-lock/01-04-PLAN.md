## Phase Goal

> ROADMAP Phase 1 goal (verbatim): "On or before 1 Dec 2026, a baseline-only Q3 FY27 revenue call for DMART, ETERNAL and TITAN is locked in an append-only, hash-chained ledger and witnessed by a GitHub commit and an OpenTimestamps proof. The call uses only data that was public at the lock instant, and the phase includes everything that cannot be changed once a lock exists."

<objective>
Vertical slice: the developer loads a quarterly-revenue CSV into an insert-only, availability-dated store. The CLI then shows that data back only through `PointInTimeReader(as_of)` and the reveal calendar.

Purpose: covers PIT-01..04, DATA-01's loader half and the strict-`<` half of LEAK-03. The store is the leakage gate's foundation, so it is append-only at the DB, and the reader asserts its own post-condition.
Output: Alembic 0002, the store writer, the reader, the seed loader, the `seed load` CLI, the reveal-calendar wiring, an empty-but-headed seed CSV with README instructions, and tests.
</objective>

    Write `0002_pit_store.py` (down_revision 0001). It creates the three tables and, for `observations` and `reveal_events`, the same append-only trigger set as 0001:
    - SQLite: `<t>_no_update`, `<t>_no_delete`, and `<t>_no_replace` (WHEN EXISTS a row colliding on any UNIQUE key).

    The `series` table is insert-only in code. Its triggers are `series_no_update` and `series_no_delete` only, so new series can still be added. Write it by hand; batch mode is not allowed.

    `store/writer.py`: `content_hash` is the sha256 of the `|`-joined fields series_key, period_date ISO, value quantized to 6 dp, available_at as `%Y-%m-%dT%H:%M:%S.%fZ`, availability_basis, source_ref, vintage and source_kind. `insert_observations` reads the existing hashes for the affected series and inserts only absent rows. It uses plain `insert()` only, with no ON CONFLICT, OR IGNORE or REPLACE (CLAUDE.md). It rejects naive datetimes and float values. `ingested_at` is a parameter; this package never reads the wall clock. `insert_reveal_events` works the same way.

    `pit/reader.py` follows the interfaces block. The constructor asserts that `as_of` is tz-aware with a zero UTC offset and that mode is in {backtest, live}. The `_row_filter` clause is `available_at < :as_of`, plus `ingested_at <= :as_of` in live mode. In Python, keep the last row per period_date by the key (available_at, ingested_at, content_hash) and return a tuple sorted by period_date. `_postcondition` raises `LeakageError` listing the offending content_hash values. `reveal_events` applies the same filter to `event_at`.

    `seed/loader.py` runs the tracer happy path. Read the file with `csv.DictReader(open(path, newline="", encoding="utf-8"))`. Map each row as follows:
    - An observation on series `rev.consolidated.<TICKER>` with `period_date = period_end` and `value = Decimal(revenue_cr)`.
    - `available_at` comes from `results_date`. A `YYYY-MM-DD` value with basis `rule:date_eod_ist` maps to D 23:59:59 IST as UTC (D-24). A `YYYY-MM-DDTHH:MM+05:30` value with basis `exchange_timestamp` is converted to UTC.
    - `source_ref` is `source_url` plus `#` and `page_ref` when present. `vintage` comes from the CSV. `source_kind` is `seed_csv` when verified is Y and `seed_csv_unverified` otherwise.
    - Reveal events are created only from `first_reported` rows: a `results` event at `results_at`, and a `business_update` event when `business_update_at` is present.

    Everything happens inside one `engine.begin()` transaction. Dry-run parses and validates but never opens a write transaction.

    The CLI gets a `seed` sub-app with command `load`. Options: `--csv PATH` (default `data/seed/quarterly_revenue.csv`), `--dry-run` and `--require-verified`. It builds `SeedCompanyRules` from the universe, passes `now=now_utc()` and prints the LoadReport counts.
